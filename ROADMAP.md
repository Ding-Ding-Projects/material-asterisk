## Build the Asterisk runtime image in CI instead of on every machine

The root filesystem is produced by building a container image that compiles Asterisk from
this checkout. That takes tens of minutes, needs a working local container engine, and —
until the tar-listing defect was fixed — had never once succeeded on a developer machine,
which is why no published installer has ever carried the payload.

- [x] Build the runtime image in the release workflow and publish it to the registry, tagged and digest-pinned by the exact source commit. Done, and verified against the registry rather than against the record that claims it: the anonymous GHCR API lists the tag `83fdd85be478ac797fcbea95342e14c6c68af40a` -- the exact source commit -- and the digest the shipped provenance names resolves to a manifest with HTTP 200. No credential was needed for either, which is also the proof the package is genuinely public.
- [x] Have the packaging step pull that image and export the root filesystem, rather than compiling Asterisk again. The application still ships the exported tar inside the installer, so nothing is pulled at run time on a user's machine and the offline guarantee is unchanged. Done. `package:squirrel` runs `bundle:asterisk`, which is `build-asterisk-wsl-bundle-from-image.ps1`: it reuses a valid bundle for the exact commit, otherwise pulls the commit-pinned image and exports its root filesystem, and only compiles when neither is available. The Windows packaging job downloads the Linux job's artifact and so takes the first path, so Asterisk is compiled once per commit rather than twice.
- [x] Record the image digest in the existing provenance file alongside the source commit and the tar's own hash, so a shipped payload can be traced to the exact image that produced it. Done. The shipped `asterisk-wsl-rootfs.json` carries `sourceCommit`, `imageRef`, `imageDigest` and the tar's own `sha256` together, so a payload on a user's machine traces to the exact image that produced it. Read back off the published release asset, not from the script that writes it.

Expected effect: the packaging step becomes a pull and an export rather than a compile, the
